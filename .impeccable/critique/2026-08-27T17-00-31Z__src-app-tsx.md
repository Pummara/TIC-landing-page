## Design Specificity Verdict

**LLM assessment:** This is genuinely authored for a Bangkok travel agency, not a reskinned template. The Services table is a real hairline-ruled manifest with alternating paper-ply tints, not a card grid pretending to be one; the notch-cut icon chips are a specific, consistently-applied motif; Carrier Partners showing 17 real, named airline logos split Full-Service/Low-Cost is a move a generic template would never make — it requires real inventory knowledge. The Contact band's full-bleed gold with ink-inverted hover is a confident, on-brand peak most B2B/B2C travel sites would replace with a generic banner. Where it slips toward generic: the hero itself is a full-bleed stock-feeling airliner photo with a headline overlay — the single most common travel-site trope there is — and its mobile execution currently undercuts the concept rather than showcasing it (see P0).

**Deterministic scan:** `detect.mjs --json src/ index.html` — exit 0, **DEGRADED** (HTML parser modules unavailable; falls back to regex matching, contrast/selector checks not evaluated), findings: `[]`. Given the DEGRADED disclaimer, "clean" here means "nothing regex-detectable," not "verified clean" — and that gap is exactly where a real defect turned up (see P1 below). The browser-injected live overlay separately flagged 4 items, 3 of which are false positives on inspection: `cramped-padding` on the hero's full-bleed wrapper (intentional edge-to-edge treatment, not missing padding), `call-caps-body` on the Thai contact address (Thai script has no case distinction, so `uppercase` is a no-op there), and `overused-font` for Inter (already a disclosed, intentional pairing with Prompt/Big Shoulders Display, suppressed in this project's own hook config — the browser overlay is a separate client-side script and can't read that suppression). The fourth, `marquee` (infinite-loop animation flagged for review), is informational, not a defect — the two Client Logos rows were verified genuinely animating (`animation-duration: 40s`, transform sampled moving over time) and correctly respect `prefers-reduced-motion`.

**Visual overlays:** Browser-DOM injection succeeded and the overlay ran (console output captured above), but no persistent on-page visual overlay was left for you to view — the live-server was stopped after evidence collection, per the critique workflow's own instruction not to leave scaffolding running. The real, higher-confidence findings from this pass came from Assessment B's own manual DOM/contrast instrumentation, not the injected overlay: a genuine WCAG AA contrast failure the CLI tool couldn't have caught in DEGRADED mode (see P1) on the Services subtitle text, present at both viewport widths and both locales.

## Overall Impression

The system is disciplined and the concept holds up under real scrutiny — I greped every gold usage in the codebase and the One Gold Rule is actually being enforced, not just documented. The single biggest opportunity is that the two places where a first-time or accessibility-dependent visitor actually *touches* the page — the mobile hero's headline/CTA legibility, and the primary button's keyboard focus ring — both have measurable, fixable defects that contradict the design system's own written rules. Neither is a taste question; both are "the code doesn't do what DESIGN.md says it should."

## What's Working

1. **The Services table** is the one place the "timetable" concept is executed with full rigor: real ruled rows (`border-b border-ink/20`), alternating `bg-paper-ply/60` tint, and a description column deliberately freed from any `max-w` cap so it fills the row instead of wrapping into unused whitespace — this matches DESIGN.md's explicit instruction, not just an accident of the CSS.
2. **Carrier Partners' white logo tiles** are a rare case of a documented, evidence-based exception to the No-Card Rule: the tiles exist because the source airline logos were supplied on black canvases and several (Finnair, Lufthansa, Singapore Airlines) are illegible on a colored ground otherwise. Design reasoning, applied consistently across all 17 marks — not decoration.
3. **The Contact band's gold discipline.** Every vivid-gold usage in the codebase sits on either a dark ground or is Contact's own full-bleed fill. The "one committed saturated color, spent only as a large block or a precise mark" rule is real, not aspirational.

## Priority Issues

**[P0] Mobile hero headline and CTAs lose legibility against the photo**
**Why it matters:** This is the first thing every mobile visitor sees, and it's the "trust and precision" positioning failing at the worst possible moment. `Hero.tsx`'s mobile scrim fades to only `ink/35` at its right edge — exactly where the uppercase "TRAVEL PARTNER" headline extends on the full-bleed mobile photo — so the right half of the headline sits nearly bare against the bright fuselage, and the CTA buttons below are similarly washed out.
**Fix:** Deepen the right-side scrim stop (e.g. `to-ink/60`) or give the headline block its own dedicated scrim independent of the ambient photo-fade gradient.
**Suggested command:** `/impeccable polish`

**[P1] Primary CTA's focus ring uses a color the system's own config says fails contrast**
**Why it matters:** `Button.tsx`'s primary variant uses `focus-visible:ring-gold`, but `tailwind.config.ts`'s own inline comment states the DEFAULT gold "fails both [3:1 and 4.5:1] on light ground," and DESIGN.md explicitly mandates `ring-gold-dark` for exactly this reason (`LanguageToggle.tsx` and the header's phone link both do this correctly). Computed: `#D4AA47` against a white ring-offset gap ≈ 2.18:1, under the 3:1 non-text minimum. The site's single most important interactive element is the weakest link for keyboard-only visitors.
**Fix:** Change `ring-gold` → `ring-gold-dark` on `Button.tsx`'s primary variant.
**Suggested command:** `/impeccable audit`

**[P1] Services subtitle text narrowly fails WCAG AA contrast on striped rows**
**Why it matters:** The English "Visa Service" / "Hotel Booking" sub-labels (`color: rgb(138,107,32)`, the documented Gold-Text shade, 14px/600) sit on the zebra-striped row background at both 375px and 1280px, in both locales. Measured with proper alpha compositing: ≈4.35–4.46:1 against the 4.5:1 requirement for normal text — a narrow, reproducible miss. This is exactly the class of defect the CLI detector's DEGRADED mode explicitly can't catch (contrast checks were disabled), and it only surfaced because Assessment B computed it directly from live computed styles.
**Fix:** Nudge Gold-Text one step darker, or drop the striped-row tint's opacity slightly so the existing shade clears 4.5:1 on both plain and striped rows.
**Suggested command:** `/impeccable audit`

**[P2] Why Choose Us breaks the page's build-up rhythm and duplicates Trust Bar's claim**
**Why it matters:** The background sequence is ink → ink → paper → paper → **ink-deep** → paper-white → gold → ink-deep. Why Choose Us is the only single-section dark island sandwiched between two light sections, right where the page should be accelerating toward Contact — it reads as an interruption, not a rising build. It also restates Trust Bar's "Professional / บริการมืออาชีพ" claim near-verbatim roughly 1500px of scroll later, without disclosing anything new at that point (Why Choose Us does have new information — 30+ years, IATA/BSP — but it's buried next to the redundant line).
**Fix:** Either merge Trust Bar and Why Choose Us into one richer proof section, or rewrite Why Choose Us to lead with the accreditation specifics instead of repeating "professional."
**Suggested command:** `/impeccable layout`

**[P2] One client logo has no real name, undermining the section's own credibility premise**
**Why it matters:** `ClientLogos.tsx`'s `partnerMark` entry is labeled `'Partner organization'` — the only generic, unnamed mark among 13 otherwise specifically-named clients (AGC Vinythai, GISTDA, KSL Group, Tourism Authority of Thailand, etc.). PRODUCT.md is explicit: "no fabricated proof... real client logos only." One anonymous mark next to twelve named ones is a small but real crack in exactly the credibility this section exists to build for a skeptical B2B visitor.
**Fix:** Confirm the real client name and use it, or drop the mark and rebalance the two marquee rows' 7/6 split.
**Suggested command:** `/impeccable clarify`

## Minor Observations

- `TrustBar.tsx` uses `IconBadge size="md"` (56px), but DESIGN.md's own component doc states Trust Bar chips should be 40px — either the doc is stale or the component regressed; worth reconciling either way.
- Trust Bar's "Best Value / คุ้มค่า คุ้มราคา" claim sits oddly against PRODUCT.md's explicit "differentiator is longevity and accreditation, not price" positioning — no pricing exists anywhere to substantiate "value," so it reads as generic filler next to three otherwise well-evidenced claims.
- `Header.tsx`'s scroll shadow (`shadow-[0_2px_0_0_rgba(12,42,77,0.08)]`) is a literal `box-shadow`, which DESIGN.md's No-Shadow Rule calls "a regression, not a style choice." Visual impact is low (hard-edged, 8% opacity, reads more like a rule line), but it's a real violation in code — swap for a background-color shift or a second border line.
- English Contact address text is markedly longer than the Thai equivalent at the same bold 24–30px size inside a 1/3-width column — likely wraps to 3–4 lines in English vs. 1–2 in Thai, unbalancing the three-column Contact grid on locale toggle.
- `src/assets/logos/client-aot.png`, `client-bem.png`, `client-giz.png`, `client-ptt.png`, `client-thaibev.png` are unreferenced by any component — orphaned assets from an older 5-client list superseded by the current 13-logo set. Harmless (unbundled by Vite) but worth deleting for repo hygiene, and PRODUCT.md's "real client logos" list is stale on this point.
